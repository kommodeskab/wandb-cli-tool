# Charts and Compare Architecture

- `charts.py` and `series.py` are UI-free logic: panel grouping (`metric.split("/")[0]` is the panel, no `/` goes to "Other", "System" is always first, plus automatic `"Tables"` and `"Images"` panels at the end when tables/images are logged), `ChartSpec(y, x, system)`, x-axis options, and row → point extraction. Keep logic there so it is testable without Textual.
- Chart kinds (`ChartSpec.kind`): **plot** (`y` + `more` = 1-8 series on one shared x-axis; all run metrics or all system metrics; chosen/edited order sets draw priority with series 0 drawn last/on top), **bar** (`y` + `more` = metrics shown as horizontal bars in the user's order, each bar the latest value: summary for run metrics, last reading for system metrics), **table** (`y` = key of a `wandb.Table`), **image** (`y` = key of logged `wandb.Image`s). Adding a chart is two steps: `ChartKindDialog`, then `PlotDialog` / `BarDialog` / `TableDialog` / `ImageDialog` (`screens/chart_dialogs.py`; `MetricPicker` is a filterable multi-select that records pick order; both plot and bar dialogs list selected metrics underneath in `#order` and reorder with `Ctrl+↑`/`↓`). Widgets are in `screens/chart_widgets.py` (`ChartView` plotext, `BarView` custom Rich, `TableView` DataTable, `ImageChartView`, all `ChartBase`, found via the `chart-widget` CSS class); Tab/Shift+Tab cycle focus panel list -> charts (the way out of a table, where arrows move the cell cursor), and `Enter` on any loaded plot, bar chart, or table opens it full-screen in `ChartViewerScreen` (`screens/chart_viewer.py`, both single-run and compared charts). UI-free logic: `palette.py`, `barchart.py` (`layout_bars`), `tables.py`. Saved layouts from before kinds existed still load (missing `kind`/`more` = plain plot).
- Colors follow the dataviz skill's reference palette (`palette.py`), unchanged: fixed slot order, never cycled (hence max 8 series), a series' color is its position in the chart (a series with no data keeps its slot), legend whenever there are 2+ series, one hue for all bars, text (names/figures) in the text color. Dark vs light values are chosen from the Textual theme. The skill's `validate_palette.js` could not be run (no node here); the palette is used as documented, which the skill records as passing its adjacent-pair checks.
- Periodic refresh (`ChartsScreen`, `refresh.py`): `_fetch_data()` (one `ChartData` bundle incl. the run's state) is shared by the first load and every refresh. A refresh (key `r`, or the timer) rebuilds the *default* layout from the new metrics under the same `custom`, then updates charts **in place** if the shown panel's specs are unchanged (keeps focus/scroll/table cursor) or remounts the panel keeping the focused index. Failures while refreshing are `quiet`: the old data stays and only the status line reports it. The timer exists only while the run is `running` and an interval is chosen (`f` cycles; saved as `chart_refresh_seconds`, default 30 s), stops itself when the run finishes, and ticks are skipped while a dialog is open or a refresh is in flight. Finished runs are never refreshed automatically.
- Image charts (`ChartSpec.kind == IMAGE`; `images.py`, `imageview.py`, `ImageChartView`/`StepSlider` in `chart_widgets.py`, `ZoomableImage`/`ImageViewerScreen` in `screens/image_viewer.py`): keys come from summary entries with `_type` `image-file` / `images/separated`; the steps come from `scan_history(keys=[key])` (bounded, sampled evenly to 1,000 steps keeping first and last). The view posts a debounced `Wanted` message when its (step, image) changes; `ChartsPane` downloads the file (content-addressed under the files cache, size-capped), makes a screen-sized thumbnail in the worker thread (`make_thumbnail` / `fetch_image` returning `(thumb, original)`) and calls `show_image(path, token, original)`; a response whose token is no longer wanted is dropped, so a slow download for a step you left never overwrites the current one. On refresh the slider keeps its step, or follows the newest if it was at the end. Both `ImageChartView` and `CompareImageView` show a fitted, non-interactive `ZoomableImage` (`interactive=False`; no zoom/fit keys, no drag) and `Enter` opens full-screen `ImageViewerScreen`, the only place (with `FileScreen`) where zoom 25%–1000% and drag exist (`imageview.py`: viewport-cropped rendering with lower-res `DRAFT_MAX_PX` frames during mouse drag + crisp settle; compared runs share one `ImageViewport`, so pan/zoom is synchronized, and adjacent compared cells in both `CompareImageView` and `ImageViewerScreen` are separated by a vertical border via `.cell-sep` / `.viewer-cell-sep`).
- Tables: a run's logged `wandb.Table`s come from the summary entries with `_type == "table-file"` (`tables.table_entries`); `table_data` downloads the `.table.json` (path-checked, 20 MB cap, 1,000 rows / 60 columns shown) and `parse_table` formats cells (media cells become `[image] name`). Only the latest version of each key is shown; tables logged inside artifacts are not.
- Metric names come from the run's *summary* (numeric values only). Default x is `_step`. System metrics come from the separate system stream (`history(stream="system")`), loaded once per `ChartsPane`/`CompareScreen`, and plot against `_runtime`/`_timestamp`. Panel/chart customizations are persisted per **project** (`layout_store.project_key(entity, project)`, stored under `"projects"` in `chart_layouts.json`; `LAYOUT_VERSION` 2 — version-1 per-run files are ignored on purpose), so every run of a project shows the same customizations on top of defaults generated from that run's OWN metrics/tables/images: `charts.py` holds `Customization` (only what the user changed: created panels, removed generated panels in `removed_panels`, added charts, x-axis/options overrides keyed by `chart_key`, edited generated specs in `edited`, never positions) and `ChartLayout` (default panels + customizations; every edit goes through its `add_panel`/`remove_panel`/`add_chart`/`set_chart`/`remove_chart`/`reset`). Customizations are re-applied on top of a freshly built default each time, so metrics/tables/images logged later still appear. `layout_store.py` (`LayoutStore`) writes them to `chart_layouts.json` in the config dir (not the cache, so logout/cache clears keep them), immediately after each change, atomically, never raising; files with another `LAYOUT_VERSION` or that are unreadable are ignored and overwritten, so **bump `LAYOUT_VERSION` in `charts.py` whenever the stored format changes** (settings may be dropped during development). `d` resets to the default after a yes/no confirmation. Deleting a chart, table or image (`Delete`/`Backspace` on a focused chart) goes through `ChartLayout.remove_chart`; deleting a panel (`Delete`/`Backspace` when `#panels` has focus) goes through `ChartLayout.remove_panel` (user panels are dropped; generated panels are recorded in `Customization.removed_panels`). A chart's index in a panel is its index among the non-removed generated charts, then among the added ones; `set_chart`/`remove_chart` both rely on `_visible_generated` for that mapping. `TableView` sizes itself to its rows (`table_height`: border + header + rows, 4..20 lines, +1 line when a horizontal scrollbar appears). Because runs differ in what they logged, `ChartsPane` decides per chart what THIS run has before fetching (`_in_this_run`, `_x_in_this_run`, built from `_metric_set`/`_system_set`): a plot draws its present series (absent ones keep their color slot and are named in the subtitle) and never requests the absent ones; a chart with nothing available (no series, missing x-axis metric, missing table/image key, all-missing bar values) calls `show_unavailable(message)` and collapses to `NOTE_HEIGHT`, and returns to full size when a refresh finds the data. Shared customizations that reference things a run lacks are harmless (`apply_customization` ignores unknown panels/keys). The screen's layout attribute is `chart_layout` because `Widget.layout` is a read-only Textual property.
- Comparing runs (`compare.py` UI-free, `runfacts.py` the run's header facts shared with `RunScreen`, `screens/compare.py`, `screens/compare_widgets.py`): `RunsScreen` keeps `selected` (run ids in pick order; Space toggles, `c` opens `CompareScreen` for 2..`MAX_RUNS` = 8 = palette size runs, `u` clears). A run's color is its position in the selection (palette slot, never cycled). `CompareScreen` fetches every run in a thread pool (`fetch_run`: details, metadata, config, metric keys/values, system rows; a failing part is empty and reported) and has four tabs: Overview (`overview_rows`, `≠` marks differing rows), Metrics (see below), Config (`flatten_config` -> dotted paths, lists up to 20 items one entry each, then `diff_config`: only entries whose values differ or that only some runs have; identical ones are counted and shown with `d`), Charts (the project's saved layout via `apply_customization` over the UNION of all runs' metrics/tables/images; `compare_charts` splits a multi-metric plot into one `ComparePlotView` per metric (small multiples, so runs x metrics never share one plot), a bar chart becomes one `CompareBarView` with a group of bars per metric and one bar per run; tables and images are compared too, see below). A plot whose runs all have exactly one point (`is_single_value`) is drawn as bars. Runs lacking a metric/x-axis are never queried and are named in the subtitle. Series are cached per (run, system, metric, x) for the screen.
- **Chart editing is shared:** `screens/chart_editing.py` (`ChartEditing` mixin: new panel, add/edit/delete chart, delete panel, reset) is used by `ChartsPane` (inside `RunScreen`) AND `CompareScreen` (Charts tab: `n a o Delete d`; the identical-rows toggle there is `i`). `Delete`/`Backspace` is context-aware (`action_delete_item`, `chart_key_label`): it deletes the focused chart/table/image, or the selected panel when the panel list is focused. The screen supplies `chart_layout`, `selected`, `panels`, `metrics`/`system_metrics`/`tables`/`images` (the UNION over the compared runs in a comparison), `_layout_key`, `_focused_chart()`, `_refresh_panel_list()`, `_show_panel(focus)`, `_update_status()`. Chart indexes in the mixin are LAYOUT positions: `CompareChart.source`/`.index` say which layout chart a drawn chart came from (a multi-metric plot is drawn as several charts but is ONE layout chart, so options/delete act on all of them). `CompareScreen.panels` is the layout's panels (empty panels included, so a new panel is visible).
- **Chart options & editing** (`ChartOptionsDialog` via `o`): edits the chart's definition and drawing options together — metrics (`MetricPicker`, pre-ticked), x-axis (`Select`), `ymin`/`ymax`, `smooth` (EMA weight 0-0.99), `logy`/`logx` for plots; metrics, bar order (`Ctrl+↑`/`↓`), and axis `ymin`/`ymax` for bars; key `Select` for tables and images. Generated charts that only changed `x`/`opts` store overrides in `Customization.x`/`opts`, while edits to a generated chart's metrics/key store the replacement `ChartSpec` in `Customization.edited`; added charts are updated in place. The stored format only gained optional fields, so `LAYOUT_VERSION` stays 2 and old files load. Smoothing/log filtering is `series.prepare_points` (`smooth_ema` is W&B's bias-corrected EMA; a log axis drops non-positive points and the subtitle says how many); widgets apply it in `show`, `chart_widgets.apply_axis_options` sets log scale and `ylim`. Compare charts honour the same options. A **bar** chart only uses `ymin`/`ymax` as the value axis (`layout_bars(low, high)`: the baseline is zero when zero is on the axis, otherwise the end nearest zero; values are clipped, the figure stays the real value).
- Compare tables/images/metrics: tables of the layout are merged by `merge_tables` into one `CompareTableView` (a Run column with the run's color; `v` = rows grouped by run / lined up by first column; 300 rows per run), images by `CompareImageView` (one shared slider over `union_steps`; each run shows `nearest_step`; downloads go through `screens/imagefetch.fetch_thumbnail`, which `ChartsScreen` uses too). In the Metrics and Config tabs `/` filters by key (`matches_filter`, one filter per tab) and `p` pins keys (`Pins`, kinds `metrics`/`config`; a pinned config key is always listed by `diff_config(pinned=...)`, a pinned row ignores the identical-rows toggle but not the filter). The Metrics tab (`metric_rows`) lists every metric's latest value per run and marks the best run. **Lower is better by default and nothing is guessed from names:** `b` flips the metric under the cursor, `B` flips all; the metrics where higher is better are saved per project in `Preferences` (`compare_higher_is_better`).
